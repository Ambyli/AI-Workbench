# ai/classifier

FastAPI service that scores documents (photos, PDFs, SVG, text, .docx; every page of every document is one item) against criteria answered by OpenCV detectors, text matching, the `ai/detector` service or a vision / text LLM chosen from the model registry `models.yaml`. Async jobs on a Postgres queue (`classifier-db`). Guide: [`API.md`](API.md). Compose: `docker-compose.classifier.yml` (`classifier-db`, `classifier`). Tests: [`API.md § Running the unit tests`](API.md#running-the-unit-tests).

## Rules

- **Postgres is the only store.** Every row (`jobs`, `job_progress`, `reference_examples`, `llm_calls`) is in `classifier-db` through ONE asyncpg pool (`db.py`, `db.pool_max()` = `CLASSIFIER_MAX_CONCURRENT` + Σ every model's `max_concurrent` + `DB_POOL_HEADROOM` 8) — a new registry entry grows the pool. No SQLite. DB unset or unreachable stops startup. `CLASSIFIER_DB_HOST` / port are fixed in the compose file, never `.env`. `jobs.result` is `JSON`, not `JSONB` (JSONB sorts keys; criteria keep request order). `job_progress` cascades with its job; `llm_calls` outlives it on purpose. [`API.md § Concurrency and durability`](API.md#concurrency-and-durability).
- **`models.yaml` is the model config, not env vars.** Bind-mounted read-only AND baked into the image (the build's import check loads it): an edit needs `docker restart classifier` (compose cannot see it). Validated at startup by `llm/models.py` (pydantic, unknown keys refused); invalid YAML, an unknown `default`, an unavailable default, a key on plain `http://` to a dotted host, a `system_line` reasoning on a Muse entry, an invalid `fast` block (a reserved key in `fast.extra_body`, `top_logprobs` < 11, `max_unseen_mass` 0, a `calibration` / `escalate_below` type other than `rating`, an `escalate_below` outside 0–100), or a `CLASSIFIER_ESCALATION_MODEL` that names no entry stops the container. Precedence: `options.model` → request `model` → `default` (`muse-glimmer`). **The one exception is `CLASSIFIER_ESCALATION_MODEL`** (`config.ESCALATION_MODEL_ENV`): the env var naming the ONE entry an `options.mode: "adaptive"` criterion escalates to (`Registry.escalation`; empty = `default`), read by `parse_registry` from the env mapping it is given — never at `config` import, so tests pass `env={...}`. Every load check stays on STATIC facts (the file and that mapping): `parse_registry` never resolves a host or opens a connection — the image build and the offline test registries call it (`test_adaptive_mode.py` blocks every lookup). An unavailable escalation entry (key unset) loads with a startup WARNING beside the `[escalation]` marker, and adaptive is then a 400 at submit. It is the entry itself (its own `ConcurrencyLimit`; `db.pool_max` unchanged), and it may be external — the operator designates it; `GET /models` `escalation` reports its host. A change needs `make up classifier` (an env change), not a restart. [`API.md § Models`](API.md#models).
- **Constants live in `config.py`; the other modules import them and hold none of their own.** Every tunable, default (a `models.yaml` block's pydantic `Field` defaults and bounds included), threshold, cap, alphabet / scale, prompt wording and the wording a caller reads (a result's `reason`, a named 400, a `detail.reference.note`) is a named constant there, in the section that names its readers; a constant several packages read has ONE home (the file is not split by package), and a function default or inline literal that repeats one imports it. `config.py` imports only the stdlib and `common.net`, so any module may import it. A constant stays a plain constant: making it an env var is a separate decision (`.env.example` + `.env` + the compose `environment:` + § Env vars). Beside their code on purpose: function registries and lookup tables (`cv.REGISTRY`, the scheduler's `EVALUATORS`, `OPTIONS_MODELS`, `llm/client.py`'s `_KIND_PREFIXES` — the table is the dispatch); result-shape declarations (root `CLAUDE.md` § Result shapes declared beside the producer); metric definitions and their label values (`metrics.py`, `llm/client.py` — one place to read what is measured); the answer contracts the parsers read (`SCORING_SCAFFOLD`, `MARKS_SCAFFOLD` — a change is code on both sides); the prompts' bodies that are assembled around per-call values, inline in `llm/prompts.py` and pinned by hash — the scoring call's user turn (its context line, which names the document kind, the truncation note, the "Score this one criterion…" instruction that spells out `SCORING_SCAFFOLD`), `ReferenceExample.caption()` and the box / verify / describe / selection prompts' own sentences. Every sentence of the scoring call's SYSTEM prompt is in `config.py` — § LLM prompt text (`SCORING_ROLE_SENTENCE`, the four `SCORING_*_SENTENCE` source sentences, `SCORING_CONFIDENCE_SENTENCE`, `JSON_ONLY_SENTENCE`, which every small call's base system prompt ends with too, before a guided call's `*_SYSTEM_SENTENCE` or a `system_line` reasoning line) and § Prompt wording (`REFERENCE_SYSTEM_SENTENCE`) — as is the wording prompts share or that is tuned on its own (§ Prompt wording); a CV detector's curve shape between its cut points (its definition; the reported cut points are config); structural key sets derived from other sets, storage / wire layout (schema versions, file names, DDL, id regexes) and endpoint plumbing (form-field sets, `_OPENAPI`); error text written at its one raise site (wording several raise sites share or tests pin verbatim moves, as fast mode's did); `Literal` types written out for type checkers (a `Literal` cannot take a variable — a test pins `typing.get_args(X) == config.TUPLE`, as for `Mode` / `FastAnswerType`); per-model values (`models.yaml`); `bin/` scripts' own constants. A `shared/common` library never imports this file (a library cannot import a service's config): it keeps its own default and takes a parameter the service fills from `config.py`. New constants go here; a pre-existing straggler moves when its code is next touched.
- **An llm result's headline `confidence` stays the model's STATED number until its entry's `confidence.calibration` is fitted and `headline: calibrated` is set** (`bin/confidence_calibration.py` measures and fits; re-fit after a model, prompt or reasoning change). How confidence is measured (`confidence.method: logprobs | sampling | stated`, default `stated`) is a per-entry knob, never a model-name branch in code; the measured signals are `detail.confidence` (shadow). The logprob payload is never stored — `llm_calls` keeps `usage` / `finish_reason` only. Sampling via `n_param` holds n slots of `max_concurrent`. [`API.md § Confidence`](API.md#confidence--measured-then-calibrated).
- **Fast mode (`options.mode: "fast"`) — and adaptive's readout — exists only on an entry with a `fast` block** — elsewhere a 400 naming the mode, where the model came from and the fast-capable ids (`Registry.fast_ids()`); no block on Muse Glimmer (its reasoning cannot be turned off), and never a model-name branch. `reads_out()` (`config.READOUT_MODES`: fast, adaptive) is the one test for "starts with the readout". Per `llm` criterion only: a request-level `mode` (JSON, multipart, `POST /references`), a criterion's top-level `mode` and `options.mode` / `options.escalate_below` on cv / text / detector are named 400s. Every check is on the VALUE, never `model_fields_set` (criteria are `model_dump()`ed into payloads and re-validated — `test_fast_mode.py` / `test_adaptive_mode.py` pin the round trip). A fast or adaptive criterion is answered but never guided: `answered_by_model()` (the model rules apply) ≠ `guided_by_llm()` (references guide it — false for both); `options.reference` on it is a 400, `POST /references` refuses explicit fast / adaptive criteria, `from_job` drops `mode` and `escalate_below` and never copies a fast unit's answer or observation, nor an adaptive unit's unless it escalated (`detail.escalation.escalated` and `status: ok` — `_readout_answered`). `identity()` (was `without_model`) drops `model`, `mode` and `escalate_below`, so `mode: "reasoned"` = unset. `options.mode` / `detail.mode` appear only when sent; a criterion without it is byte-identical (the reasoned prompts and bodies are pinned by hash in `test_fast_mode.py` and `test_reference_prompts.py`; `FAST_GOLDEN` pins the fast prompt — change the `FAST_*` wording in `config.py` § Prompt wording only on purpose; the `SCORING_*` sentences in § LLM prompt text — the role and three of the source sentences are in both prompts — are pinned by `GOLDEN`, `REASONED_PROMPT_PINS` and `FAST_GOLDEN`: the same). Its constants follow the `config.py` rule above: the readout's scale (`FAST_DIGITS`, `FAST_SCORE_OFFSET`) beside its wording, the rest in § Fast mode. The box loop after a fast score runs reasoned, as today. [`API.md § Fast mode`](API.md#fast-mode--a-one-token-readout).
- **A readout is posted ONCE and never retried** (`llm.client.call_readout`, label `fast/<name>`, call kind `fast` — its `_KIND_PREFIXES` row stays ahead of the generic ones): the same prompt gets the same logits. `ReadoutIncomplete` is deliberately NOT a `ValueError`, so nothing mistakes it for a parse failure. Coverage under `fast.min_coverage` (or no logprobs) is `ReadoutIncomplete`; the probability cap — `unseen_bound` (an estimate — a heuristic, not a guarantee — of what labels missing from the top-k hold) ≥ `fast.max_unseen_mass` — is `ReadoutCapped`, naming `fast.top_logprobs` and `--max-logprobs`; either fails the unit in mode fast ("… — use mode 'reasoned' for this criterion", `config.FAST_UNIT_ERROR_FIX`) and escalates in mode adaptive, and counts in `classifier_readout_incomplete_total{model, kind, reason}`; a server 4xx about logprobs becomes "the server refused top_logprobs K". **A fast result's headline `confidence` is its readout** — the winning band's mass, headline `readout` — after the entry's `fast.calibration.rating` temperature when one is fitted (headline `calibrated`); it is not the stated-shadow rule above (a readout states nothing: `stated` null). `bin/confidence_calibration.py --mode fast` fits that temperature and prints the escalation curve that sets `fast.escalate_below`.
- **Adaptive (`options.mode: "adaptive"`) = the readout, then — only when unsure — the ESCALATION model's reasoned scoring call** (`analysis/llm_eval.py` `_adaptive` / `_escalate`). It escalates on `ReadoutIncomplete` / `ReadoutCapped` or when the readout's headline confidence (computed even under `score: false`) is under the threshold — `options.escalate_below` (0–100, a named 400 on any other mode), else the criterion's model's `fast.escalate_below.rating` (filled at load with `config.FAST_DEFAULT_ESCALATE_BELOW`, 80). The escalation is today's reasoned prompt on `Registry.escalation` — ITS text budget, vision, reasoning, budgets and `confidence.method`, never reference-guided — label `escalate/<name>`, call kind `escalate` (its `_KIND_PREFIXES` row stays ahead of the generic ones; `_SCORING_KINDS` measures it like `score`). The escalated answer is the unit's (`detail.model` the escalation id, `detail.mode` `reasoned`); else the readout's (`detail.mode` `fast`). `detail.escalation` (`ESCALATION_KEYS`, its `fast` `ESCALATION_FAST_KEYS`) is declared on `LLM_RESULT`; `clear_judgement` nulls its `signal` and `fast.score` / `verdict` / `confidence` under `score: false`, where an unparseable escalation answer (`llm.client.AnswerUnparsed`, whose message quotes the answer's start — a verdict and confidence) is reported as `config.ESCALATION_UNPARSED_UNJUDGED`, never quoted (the log line keeps it). A failed escalation (HTTP, timeout, unparseable, the entry unavailable at run time, a text-only escalation model with no text) keeps a complete readout (`escalated: false`, `error`); only an unreadable readout whose escalation failed errors the unit (`ADAPTIVE_BOTH_FAILED`). The box loop stays on the criterion's own model, reasoned. Submit: the criterion's model needs a `fast` block, the escalation entry must be available (`ADAPTIVE_ESCALATION_UNAVAILABLE`), and a text-only escalation model is refused on a photo with no OCR (`api/assess._check_documents`). Counted in `classifier_escalations_total{model, why: confidence | incomplete | cap, outcome: ok | failed}`. [`API.md § Adaptive mode`](API.md#adaptive-mode--escalate-when-unsure).
- **Keys never live in the YAML.** An entry's `api_key_env` names an env var that must ALSO be listed in the compose `environment:` as `- VAR=${VAR:-}`; unset → `available: false`, selecting it is a 400. `GET /models` never returns a key.
- **Muse Glimmer reasoning rides as `chat_template_kwargs: {reasoning_strength: low}`.** Its stock template renders "Reasoning strength: low." itself and a system-prompt reasoning line would OVERRIDE it — never add one (load refuses `system_line` on Muse).
- **`max_images_per_prompt` never exceeds the server's image limit** (entry ≤ server; 3 = contrastive references, 2 = one example per call, 1 = none): vLLM's `--limit-mm-per-prompt`, which is 999 when the flag is unset (not one). `muse-glimmer` runs `'{"image": 3}'` for its 3; `qwen3.8-solo` sets no flag (probed: 3 accepted). Raising an entry above a flag rejects every reference-guided call — recreate the server first. [`API.md § Deploying this version`](API.md#deploying-this-version).
- **Text-only entries (`vision: false`)** refuse boxes, references and image-only work at submit; each model's `timeout_s` bounds one non-streamed request and a timeout is not retried.
- **Limits, outer to inner:** `CLASSIFIER_QUEUE_LIMIT` (admission: OPEN jobs — `staging` + `pending` + `processing`, waiting AND running — past it a submit is a 429 + `Retry-After`; 0 = none) → `CLASSIFIER_MAX_CONCURRENT` (jobs) → `CLASSIFIER_MAX_UNITS_PER_JOB` (units of one job, a per-job `asyncio.Semaphore` in `analysis/scheduler.py`) → per-model `max_concurrent` (held in `llm/client.py` around the HTTP request, every call kind) and `CLASSIFIER_OCR_WORKERS` (process-wide `common.jobs.limits.ConcurrencyLimit`). A unit = (criterion, item); a `text` criterion with `scope: "document"` is one unit per document.
- **The queue limit is checked twice and answered once.** `ClassifierQueue.check_room` (first line of `POST /assess` / `POST /references`, before the body is read — a full queue costs no URL / SVG fetch; one `count_open()`, no lock) and `ClassifierQueue.admit` (THE registration — `register(..., "staging", max_open=)`, counted and inserted in one transaction behind `pg_advisory_xact_lock`, so the last slot goes to one submit; never call `jobs_registry.register` from a submit endpoint). Both raise `QueueFullError` (`jobs/` never imports FastAPI); `main`'s exception handler is the one 429 (FastAPI `detail` shape, `Retry-After`, `classifier_jobs_rejected_total`, one INFO line). `Retry-After` is `retry_after_estimate` — the median of the last 50 completed / failed run times × slots needed ÷ `min(limit, MAX_CONCURRENT)`, 2–60 s, 10 with no history; constants in `config.py`, never env vars. A reference's admit stays BEFORE `reference_registry.create`. Lower the limit below 32 on the box only once every caller waits `Retry-After` and resubmits (ZT-526). [`API.md § Concurrency and durability`](API.md#concurrency-and-durability).
- **Drain the queue before a payload-schema change** (`schema: 3` today): an old payload is refused by the new runner and the job fails. Restart requeues `processing` rows.
- **The box loop never changes a score or a verdict**; it runs after scoring. Rejection wording is the retry's prompt — changing it changes behaviour. Re-run `bin/grounding_experiment.py` before trusting a new model or a new `CLASSIFIER_LLM_BBOX_GRID_STEP`. [`API.md § The LLM enforcement loop`](API.md#the-llm-enforcement-loop).
- **The box loop's settings are per criterion; the env vars are only the service defaults.** An `llm` criterion's `options.refine` (`grid` | `marks`), `options.verify_partial`, `options.verify_min_span` (0–1), `options.reference.boxes` (`{ask, refine, verify}`) and `options.reference.text` each override `CLASSIFIER_LLM_BBOX_REFINE_MODE` / `_VERIFY_PARTIAL` / `_VERIFY_MIN_SPAN`, `CLASSIFIER_REFERENCE_BOX_ASK` / `_REFINE` / `_VERIFY`, `CLASSIFIER_REFERENCE_BOX_TEXT`; unset (null) = the env default, OFF. They need `boxes: true` (a 400 naming each otherwise, as `position: "check"`), are unknown keys on `text` / `detector` / `cv` (`reference.boxes` / `.text` refused by name on `cv`), and `options.reference.*` still needs `references`. `api/criterion_options.py` resolves them — `resolve()` fills the default in so `options_used` shows what RAN, `box_loop_settings()` hands `analysis/llm_eval.py` the keywords — the one place the service reads those env vars (tests patch them THERE); `llm/boxes.py` / `analysis/references.py` keep module defaults only for direct callers (`bin/grounding_experiment.py`). `CLASSIFIER_LLM_BBOX_MARKS_MAX` stays service-wide. No payload-schema bump (a payload / stored reference without the keys runs as before); `references.resolve._same` compares the RESOLVED values. **The classifier deploys before any caller sends them** (unknown keys are a 400 on an older build) — ZT-526's Operations Assistant included. [`API.md § The box loop's options`](API.md#the-box-loops-options--per-criterion).
- **The loop's opt-in aids are off = today, byte for byte** (`refine: "grid"`, `verify_partial: false`, `verify_min_span: 0`, `reference.text: false` — the defaults; pinned in `test_reference_prompts.py` / `test_llm_box_marks.py` / `test_box_loop_options.py`): their attempt keys (`refine_mode`, `marks`, `marks_shown`, `marks_lines`, `marks_fallback`, `verify_partial`) exist only when on, their wording is `config.py § Prompt wording`. Marks numbers the first of three tiers with a line in its window (`marks_lines`, all ORIGINAL page pixels): the PDF / SVG page's own lines (`TextLayer.native_lines` — never in `TextLayer.lines` / `ocr_lines`, which `textmatch` maps text offsets through), `llm_eval`'s OCR layer (`TextLayer.lines`, never a second pass of the page), then OCR of the window alone (`DocumentContext.window_lines`, injected — `llm/` never imports `analysis`; never under `ocr: "never"`; None / an error is a grid fallback, never a failed unit); a tier over the cap falls back without trying the next; every frame change is a named function in `llm/boxes.py` (`window_rect`, `to_crop_px`, `pixels_to_grid`).
- **The box loop sees reference examples only behind a criterion's `options.reference.boxes`** (default: the three `CLASSIFIER_REFERENCE_BOX_*` knobs; all off = byte-identical prompts, pinned by hash in `test_reference_prompts.py`): examples with regions only, FAIL only when the reference criterion's hint is `presence`, region crops (not composites) for the ask under the position check. `llm/` never imports `analysis` (the loop hands `llm_eval` a log of its guided calls). Loading an example never fails the unit. [`API.md § What the model is shown`](API.md#what-the-model-is-shown-and-what-it-costs).
- **References are not swept.** `CLASSIFIER_REFERENCE_DIR` must stay outside `CLASSIFIER_ARTIFACT_DIR` (the sweeper deletes every directory whose job row is gone); only `DELETE /references/{id}` removes one; `CLASSIFIER_REFERENCE_MAX_COUNT` bounds the disk.
- **A criterion's `key` is for reference matching only.** Order `options.reference.criterion` (a reference criterion NAME) → `key` → `name`, case-folded, one rule in `references.resolve.match_target`; a keyed criterion never falls back to its name; keys may repeat on `/assess` but are unique within a reference (`check_unique_keys`; PATCH `criteria_keys` is the one edit a ready record takes). Results, `depends_on`, prompts and file names stay on `name` — the key never reaches a prompt. A plan without `matched_by` means `name`. [`API.md § How a criterion finds its examples`](API.md#how-a-criterion-finds-its-examples--the-matching-order).
- **The artifact byte cap never drops the evidence** (`regions.json`, `manifest.json`, `text.*.json`, the SVGs).
- **The worker never touches the network for input**: URLs and opt-in SVG `<image>` links are fetched at SUBMIT through `common.net.fetch_url` (SSRF guard, no redirects).
- **`POST /assess` is the only analysis endpoint**; `/locate` and `/assess/compare` are gone (404). Geometry without judgement is `"score": false`.
- **`GET /jobs/{id}?wait=` long-polls** (`build_router(terminal_phases=("completed", "failed", "cancelled"), max_wait_s=JOB_WAIT_MAX_S)` in `main.py`): the cap `config.JOB_WAIT_MAX_S` (60) is a constant under Cloudflare's ~100 s on `api.zeoenergy.com` — never an env var, never past 100. A new phase a job can END in joins `terminal_phases` (and the pollers' own terminal tuples: route-policy's `_TERMINAL_PHASES`, `bin/reference_box_assess.py`'s `JOB_TERMINAL`, `regions_report.py`'s `TERMINAL_PHASES`), or every wait on it runs to the cap. Pollers send `wait=min(30, left)` and sleep their old interval after a fast non-terminal answer (an older build ignores `wait`) — the gateway meters every poll. [`API.md § GET /jobs/{job_id}`](API.md#get-jobsjob_id).
- **`POST /jobs/{id}/cancel` is a phase flip plus the pool's watcher.** The registry flips the row to `cancelled` in one transaction (409 on a finished job); the `WorkerPool` is cancel-aware (`cancel_check_interval=config.CANCEL_CHECK_INTERVAL_S`, 1 s, a constant — never an env var): it re-reads each running job's row, cancels `handle_job` on `cancelled` or a row gone (a DELETE of a running job is a cancel too), and stores a result only while the row is still `processing` (guarded writes). `ClassifierQueue.finish_cancelled` is THE one cleanup (payload, `cancelled` progress, a reference job's reference, a deleted job's late usage rows / artifacts) — called by the router's `on_cancel` hook for a `staging` / `pending` job, by the pool's `on_cancel` for a running one (in the worker task, AFTER `handle_job` unwound), and by `enqueue` when its guarded `staging` → `pending` flip misses; idempotent, never raises. A `CancelledError` in `handle_job` never decides the cleanup — shutdown and cancel look the same there, and both keep the payload. Never mount the cancel route over a pool without `cancel_check_interval`: the job would run on and its result overwrite the cancel. [`API.md § POST /jobs/{job_id}/cancel`](API.md#post-jobsjob_idcancel).
- **The trino_reader init script (`db-init/10-trino-reader.sh`) must stay safe to SOURCE**: the postgres entrypoint sources a script without an exec bit — no `exit`, no `set`.
- **A new subpackage under `ai/classifier/` needs its own `COPY` line in the `Dockerfile`** (one per subpackage, no `.dockerignore` on purpose); the build's import smoke turns a forgotten one into a build failure.
- **An API change updates `classifier.postman_collection.json`, `classifier.schemas.json` and `API.md`** together (`scripts/api_schemas.py render` writes the schemas into the collection and the generated `API_SCHEMAS.md`; root `CLAUDE.md` § Postman collections). The JSON request models (`AssessRequest`, `ReferenceRequest`, `ReferencePatch`), `CriterionInput`, the jobs models, each type's `detail` and each detector's `measurements` are generated — `API_SCHEMAS_UPDATE=1` on `unit-tests/classifier/test_api_schemas.py` rewrites them; the rest (the result envelope, the introspection payloads, references, usage, progress, the artifact manifest) is hand-written and closed, and that test validates real output without Postgres (`analyze_document` with a scripted model, the artifact routes over a registry stub, the introspection routes) — the Postgres-backed routes are checked by `unit-tests/apidocs` only. A new key in the result envelope or a criterion entry updates `classifier.schemas.json` (and `unit-tests/classifier/result_shape.py`'s `ENTRY_KEYS`) in the same change.

## Result shapes

The standard: root `CLAUDE.md` § Result shapes declared beside the producer. Here:
- An OpenCV detector's `detail` — `@describes(DetectorSpec(...))` on the detector function (`cv/result.py`); the detector `REGISTRY` is the lookup, `GET /cv-detectors` serves it, `unit-tests/classifier/test_cv_measurements.py` checks it.
- A criterion type's `detail` — `@result_spec(ResultSpec(...))` on its evaluator (`analysis/{llm,text,detector,cv}_eval.py`), registered by type name in `analysis/result_specs.py` (looked up by the aggregator, the scheduler and `GET /criterion-types`); a new type's module is also listed once in `result_specs._DECLARING_MODULES`. `unit-tests/classifier/test_result_specs.py` checks it. The `detail_<type>` schemas in `classifier.schemas.json` (and `detail_<type>_mean`, the stable keys a `mean` keeps — with the FIRST member's values, which may differ from another member's: `image_sent` across mixed documents, an adaptive criterion's `model` / `mode`; each unit's are in `items[]` — plus the rebuilt keys) are generated from it, and the cv `measurements_<function>` ones from each `DetectorSpec` (`test_api_schemas.py`).
- **A key that summarises the members is declared `rebuild=<combiner>`** (`FieldSpec`, served `rebuilt: true`; never also `stable`): `result_specs.aggregated_detail` rebuilds it from ALL the counted members at both levels under EVERY rule — never the chosen (any / worst) or first (mean) member's — and `mean` keeps it. Each unit carries its own value and the combiner takes its own output back, so the levels nest (documents = the sum of their pages). Today: the llm `escalations` tally (`llm_eval.combine_escalations`; units 1 per page, so a single-page criterion has it too; wording `config.ESCALATIONS_SUMMARY*`). A type without one aggregates byte-identically.
- **A `FieldSpec.kind` is one of `result_specs.KINDS`** (number, integer, string, boolean, array, object — a JSON Schema type; anything else is refused where it is declared), and **`nullable=True` marks a value that may be null** (served as `nullable: true`; the generated schema allows `null` only there). A field whose value can be null without it fails `test_api_schemas.py`.
- `detail.reference` is ONE shared declaration, `REFERENCE_FIELD` in `analysis/result_specs.py`, listed on `LLM_RESULT` only — a `cv` criterion answered by the llm fallback carries it through the llm shape.
- Adding a detector, a type, or a key to a `detail` updates its declaration in the same change. [`API.md § Result details`](API.md#result-details--the-same-shape-on-every-type).

## Cross-folder rules

Also in the root `CLAUDE.md` § Cross-folder rules — read the named entry there for the full picture.

- **Local vLLM slots** — the `muse-glimmer` entry's `max_concurrent: 6` is 6 of vLLM's `--max-num-seqs 8` (`ai/vllm`), leaving 2 for LiteLLM chat; filling all 8 makes the overflow hook spill chat to Claude. The `qwen3.8-solo` entry's `max_concurrent: 3` = all of its `--max-num-seqs 3`, which chat shares (decision 2026-11-12: while the classifier holds all three, a chat turn queues and the overflow hook spills it to the chain's next order). `CLASSIFIER_MAX_UNITS_PER_JOB` (6) is matched to the default model's `max_concurrent`. Watch `classifier_llm_call_seconds{kind, model}` before raising either. (root `CLAUDE.md` § Cross-folder rules)
- **Image limit per prompt** — an entry's `max_images_per_prompt` ≤ its server's limit: the `muse-glimmer` entry's 3 = its vLLM `--limit-mm-per-prompt '{"image": 3}'`; the `qwen3.8-solo` entry's 3 ≤ vLLM's default 999 (no flag) (`ai/vllm` compose). Raise the server first, or every reference-guided call is rejected. (root `CLAUDE.md` § Cross-folder rules)
- **Fast readout logprobs** — an entry's `fast.top_logprobs` ≤ its server's `--max-logprobs`: the `qwen3.8-solo` entry's 64 = its vLLM `--max-logprobs 64` (`ai/vllm` compose; vLLM's default is 20). Raise the server first (`make up vllm qwen3.8-solo`), then the entry (`docker restart classifier`); lower the entry first. Over the server's ceiling every readout errors ("the server refused top_logprobs K"); a readout whose unseen labels could hold `fast.max_unseen_mass` errors as the probability cap, naming both knobs. (root `CLAUDE.md` § Cross-folder rules)
- **`qwen3.5-4b` sizing** — its entry's `max_concurrent: 2`, `max_tokens.score: 512`, `text_char_budget: 12000` match the llama.cpp service's `--parallel 2`, `--n-predict 512`, `-c 32768` (`ai/llama`); route-policy's `ROUTE_POLICY_ANALYSIS_CONCURRENCY` (2) equals that `max_concurrent`, and its ruleset `history.max_chars` must stay ≤ 12000. Change together. (root `CLAUDE.md` § Cross-folder rules)
- **Classifier as route-policy's model runner** — route-policy's `llm_classifier` calls `POST /assess`, `GET /models`, `GET /jobs/{id}`, `POST /jobs/{id}/cancel`, `DELETE /jobs/{id}` (it cancels an unfinished job, then always deletes; a cancel frees its `qwen3.5-4b` slots within ~1 s); it submits only to an entry that is `authenticated: false`, `available: true` and resolves to private addresses. It sends no `options.mode`; were it to send `adaptive`, a page could escalate to `CLASSIFIER_ESCALATION_MODEL` (may be external), so its guard would also have to check `GET /models` `escalation`. Changing those endpoints' shapes breaks `ai/route-policy/route_policy/analysis/`. Route jobs share this service's FIFO with document jobs, and its limit: a full queue (`CLASSIFIER_QUEUE_LIMIT`) answers 429, which route-policy records as `unavailable` (no job id, so nothing to cancel or delete). (root `CLAUDE.md` § Cross-folder rules)
- **Trino reads other stacks' Postgres** — `classifier-db` is federated as `postgres_classifier` (`ai/trino/catalogs/postgres_classifier.properties`) through the read-only `trino_reader` role made on the FIRST start of an empty `classifier_db` volume; `CLASSIFIER_TRINO_READER_PASSWORD` is also in `trino-coordinator`'s env. Retrofit / rotate: [`API.md § Concurrency and durability`](API.md#concurrency-and-durability). Trino reaches `classifier-db:5432` by service DNS, not `PORT_CLASSIFIER_DB`. (root `CLAUDE.md` § Cross-folder rules)
- **Deploy order across stacks** — `docker restart classifier` after a `models.yaml` edit; recreate `muse-glimmer` (`make up vllm muse-glimmer`) before the classifier when the entry's image count or concurrency rises, and `qwen3.8-solo` (`make up vllm qwen3.8-solo`) before it when its `fast.top_logprobs` rises (its `--max-logprobs`); drain the queue before a payload-schema change. (root `CLAUDE.md` § Cross-folder rules)
- **Swap-class services publish through the edge** — the classifier is recreate-class (startup requeues the running copy's jobs) but FRONTED by `ai/edge` on `PORT_CLASSIFIER` 8005 (no `ports:` of its own), so a restart answers `503` + `Retry-After`; no auth on the service — LAN access is `EDGE_ALLOWED_CIDRS`, the bearer check is LiteLLM's pass-through. (root `CLAUDE.md` § Deploys (`make up`))
- **LiteLLM pass-throughs carry the auth** — the service checks no token; `/v1/classifier` in `ai/litellm/litellm_config.yaml` `pass_through_endpoints` carries `auth: true` and its `methods` must include `PATCH` (for `PATCH /references/{id}`). A new route without `auth: true` is open to keyless callers (`ai/litellm/LITELLM.md § Pass-through auth`). (root `CLAUDE.md` § Cross-folder rules)

## Env vars

One line each; full detail in `.env.example` (Classifier block) and the `API.md` section named.

- `CLASSIFIER_MAX_CONCURRENT` (`4`) — jobs at once (worker tasks claiming from `jobs`); the job-level knob, not the model-load one; `1` = serial.
- `CLASSIFIER_QUEUE_LIMIT` (`0` = no limit; `32` recommended on the box, which refused nothing in a day's traffic) — jobs waiting OR running at once; past it `POST /assess` / `POST /references` answer 429 + `Retry-After`. = `MAX_CONCURRENT`: nothing waits; below: idle workers (startup WARNs); above: `limit − MAX_CONCURRENT` may wait. [`API.md § Concurrency and durability`](API.md#concurrency-and-durability).
- `CLASSIFIER_MAX_UNITS_PER_JOB` (`6`) — units one job runs at once; matched to the default model's `max_concurrent`; lower it to stop a big job crowding others. (Renamed from `CLASSIFIER_MAX_CRITERIA_PER_JOB`.)
- `CLASSIFIER_ESCALATION_MODEL` (empty = the registry `default`, `muse-glimmer`) — the ONE `models.yaml` entry an `options.mode: "adaptive"` criterion escalates to; read by `llm/models.parse_registry` (`config.ESCALATION_MODEL_ENV`), the one model setting that is an env var (rule above). An id naming no entry stops startup; an unavailable entry WARNs and adaptive is a 400; it may be external (`GET /models` `escalation`). A change needs `make up classifier`. [`API.md § Adaptive mode`](API.md#adaptive-mode--escalate-when-unsure).
- `CLASSIFIER_OCR_WORKERS` (`4`) — OCR passes at once, all jobs; OCR is memoised per item by its settings.
- `CLASSIFIER_PROGRESS_FLUSH_INTERVAL_S` (`1`, floor `0.2`) — progress snapshot + `job_progress` write cadence; terminal state always written. [`API.md § Progress`](API.md#progress).
- `CLASSIFIER_DB_USER` / `_PASSWORD` / `_NAME` (`classifier` ×3) — dev defaults; override the password before exposing the DB. DSN quoted with `urllib.parse.quote`.
- `CLASSIFIER_TRINO_READER_PASSWORD` (unset) — set BEFORE the first start of an empty volume; empty skips the role (only the Trino catalog breaks); a real secret (`openssl rand -hex 32`).
- `PORT_CLASSIFIER` (`8005`, published by the edge) / `PORT_CLASSIFIER_DB` (`5439`, psql / DBeaver only) — `.env` PORT REGISTRY, Postgres group (root `CLAUDE.md` § Env vars and the PORT REGISTRY).
- `JOB_TTL_HOURS` (`24`) — terminal jobs and their artifacts expire; `pending` / `processing` are never swept.
- `CLASSIFIER_OCR_ENGINE` (`rapidocr`) — `none` disables OCR; `text` criteria on image-only pages then fail. Models are pre-warmed in the Dockerfile. [`API.md § OCR`](API.md#ocr).
- `CLASSIFIER_OCR_MIN_NATIVE_CHARS` (`20`) — below it `ocr: "auto"` treats a page as a scan.
- `CLASSIFIER_PDF_RENDER_DPI` (`150`) — PDF / SVG render density; pages are then shrunk to ≤1000 px, so higher mostly buys OCR accuracy.
- `CLASSIFIER_MIN_IMAGE_WIDTH` / `_HEIGHT` (`32` / `32`) — thumbnail-catcher only (was 100×100, which broke one-line crops).
- `CLASSIFIER_MAX_ITEMS` (`20`, inclusive) — items (pages) per request; 21 is a 400 naming each document's page count. [`API.md § Items and the cap`](API.md#items-and-the-cap).
- `CLASSIFIER_CRITERION_NAME_MAX_CHARS` (`200`) — 422 past it; the `llm` name is the prompt and is slugified into file names.
- `CLASSIFIER_TEXT_MIN_COUNT_CAP` (`1000`) — max `options.min_count`. The 500-char pattern cap is in `common.documents.textmatch`, not a knob.
- `CLASSIFIER_SVG_FETCH_IMAGES` (`false`) / `_MAX_IMAGES` (`10` distinct) / `_MAX_BYTES` (`5000000`) / `_TIMEOUT_S` (`10`, wall-clock) — opt-in SVG `<image>` inlining at submit. [`API.md § External references in SVG`](API.md#external-references-in-svg).
- `CLASSIFIER_ARTIFACT_DIR` (`/data/artifacts`) — per-job artifact dirs on the `classifier_data` volume. [`API.md § What a job writes, and what renders on first fetch`](API.md#what-a-job-writes-and-what-renders-on-first-fetch).
- `CLASSIFIER_ARTIFACT_SWEEP_INTERVAL_S` (`600`) — sweeper cadence (also at startup); deletes expired dirs AND job rows — what makes `JOB_TTL_HOURS` real.
- `CLASSIFIER_ARTIFACT_MAX_BYTES` (`50000000`) — byte cap PER ITEM. [`API.md § Disk and retention`](API.md#disk-and-retention).
- `CLASSIFIER_INLINE_REGIONS_MAX` (`50`) — regions per criterion inline in the result (`regions_truncated`); raising it slows `GET /jobs`.
- `CLASSIFIER_LLM_BBOX_MAX_ATTEMPTS` (`3`) — box-loop rounds and the CAP on `options.max_attempts` (over it is a 400); ≤ 3 calls per attempt (4 with `refine: "marks"` when a marks answer falls back to the grid refine).
- `CLASSIFIER_LLM_BBOX_VERIFY_PASS` (`7`) — score the isolated crop must earn.
- `CLASSIFIER_LLM_BBOX_MIN_AREA` / `_MAX_AREA` (`0.002` / `0.95`) — box area bounds; full-frame boxes are the commonest failure.
- `CLASSIFIER_LLM_BBOX_CROP_PAD` (`0.25`) — verify-crop padding (was 0.10; the refine pass draws tight boxes).
- `CLASSIFIER_LLM_BBOX_GRIDLINES` (`true`) / `_GRID_STEP` (`100`, a divisor of 1000, floor 10) — grid on the ask image.
- `CLASSIFIER_LLM_BBOX_REFINE` (`true`) / `_REFINE_ZOOM` (`2.5`) / `_REFINE_MIN_SPAN` (`0.2`) — the zoomed second ask.
- `CLASSIFIER_LLM_BBOX_REFINE_MODE` (`grid`) — service default; per-criterion `options.refine` overrides. `marks` numbers the text lines in the refine window (a digital PDF's own, else the criterion's OCR layer, else OCR of the window; `marks_lines` says which) and asks which; the box is their union — for text fields, not charts / logos. Grid fallback, recorded as `marks_fallback` (naming the tiers tried), on no line in the window / over the cap / an unusable or null answer. [`API.md § The LLM enforcement loop`](API.md#the-llm-enforcement-loop).
- `CLASSIFIER_LLM_BBOX_MARKS_MAX` (`40`) — service-wide (no option): more text lines in the window (in the tier reached) than this refines on the grid.
- `CLASSIFIER_LLM_BBOX_VERIFY_PARTIAL` (`false`) — service default; per-criterion `options.verify_partial` overrides. The verify also answers `partial` (cut off); never moves the score; a rejected partial crop's retry says "same place, larger" (`config.VERIFY_PARTIAL_REJECT`).
- `CLASSIFIER_LLM_BBOX_VERIFY_MIN_SPAN` (`0`) — service default; per-criterion `options.verify_min_span` overrides. Verify crop grown, centred, inside the page, to this share of the page on each axis; the box and the record are unchanged.
- `CLASSIFIER_REFERENCE_DIR` (`/data/references`) — never under the artifact dir. [`API.md § References`](API.md#references).
- `CLASSIFIER_REFERENCE_MAX_COUNT` (`500`) — 409 past it; the only disk bound on references.
- `CLASSIFIER_REFERENCE_MAX_PER_REQUEST` / `_MAX_PER_CRITERION` (`10` / `3`) — explicit ids per `/assess`; examples (and extra scoring calls) per criterion.
- `CLASSIFIER_REFERENCE_AUTO_POOL_MAX` / `_AUTO_MIN_CONFIDENCE` (`20` / `60`) — `references: "auto"` pool and match floor; the selection runs on the JOB's model.
- `CLASSIFIER_REFERENCE_POSITION_MIN_IOU` / `_MAX_OFFSET` / `_CAP` (`0.3` / `0.15` / `5`) — opt-in position check; a miss caps, never raises; no model call.
- `CLASSIFIER_REFERENCE_DESCRIBE` / `_DESCRIPTION_MAX_CHARS` (`true` / `500`) — auto-describe a reference page; also the max caller description.
- `CLASSIFIER_REFERENCE_BOX_ASK` / `_REFINE` / `_VERIFY` (`false` ×3) — service defaults; per-criterion `options.reference.boxes.{ask,refine,verify}` overrides each. Show reference examples to the box loop's ask / refine / verify calls. Measured (ZT-527): turn the three on TOGETHER per criterion (VERIFY alone made passing pages worse); the defaults stay off, and a document opts in. [`API.md § The LLM enforcement loop`](API.md#the-llm-enforcement-loop).
- `CLASSIFIER_REFERENCE_BOX_TEXT` (`false`) — service default; per-criterion `options.reference.text` overrides. Each box-loop example's caption quotes its region's text (OCR of the reference page's region, once per job, ≤ 80 chars); no text or an OCR failure = today's caption.
- `DETECTOR_URL` (empty = off) — `http://detector:8000` once `ai/detector` is up; empty refuses `detector` criteria at submit; set, a `cv` name with no OpenCV detector defaults to `fallback: "detector"`. Unreachable fails only the criteria that asked (`status: "error"`). [`API.md § The detector`](API.md#the-detector).
- `DETECTOR_MIN_SCORE` (`0.25`) — used twice on purpose: the detector `threshold` AND the PASS line for box-scored criteria (≥0.5 → 10, above the floor → 7, else 1).
- `DETECTOR_TIMEOUT_S` (`30`) — one `POST /detect`.
- `DETECTOR_MAX_LABELS_PER_CALL` (`16`) — keep ≤ the detector's `DETECTOR_MAX_LABELS` (32); more labels are split, not refused.
- Removed with no fallback (startup WARNs if set): `VISION_LLM_API`, `VISION_LLM_MODEL`, `CLASSIFIER_REASONING_STRENGTH`, `VISION_LLM_MAX_TOKENS`, `VISION_LLM_MAX_IMAGES_PER_PROMPT`, `CLASSIFIER_MAX_LLM_CALLS`, `CLASSIFIER_HTTP_TIMEOUT_S`, `CLASSIFIER_LLM_BBOX_MAX_TOKENS`, `CLASSIFIER_REFERENCE_SELECT_MAX_TOKENS`, `CLASSIFIER_TEXT_CHAR_BUDGET` — their job is `models.yaml` now.
- Compose-fixed, never `.env`: `CLASSIFIER_DB_HOST` (`classifier-db`), `CLASSIFIER_DATA_DIR` (`/data`), `PAYLOAD_DIR` (`/data/payloads`).
