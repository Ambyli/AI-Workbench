# ai/litellm

The single OpenAI-compatible surface: `litellm` (swap-class, fronted by `ai/edge` on `PORT_LITELLM` 4001 and TLS 443), `litellm_db` and `prometheus` (both recreate-class). Chat goes through four **chain aliases**; `auto` is decided per request by route-policy. Guide: [`LITELLM.md`](LITELLM.md) (chains, overflow hook, footer, hooks package, route-policy client); MCP tool calling: [`LITELLM_MCP.md`](LITELLM_MCP.md). Compose: `docker-compose.litellm.yml`; config: `litellm_config.yaml`; hooks: `hooks/` loaded through the `overflow.py` shim. Tests: `unit-tests/litellm/` (`LITELLM.md § The hooks package` has the commands and the `litellm[proxy]==1.95.0` venv for the proxy-plumbing tests).

## Rules

- **Chains.** `local-general` / `local-code` = `qwen3.8-solo` → `muse-glimmer` → `claude-sonnet-5`; `local-reasoning` = `muse-glimmer` → `qwen3.8-solo` → `claude-opus-5-5`; `local-private` = `qwen3.8-solo` → `muse-glimmer`, **no Claude**. Claude is order 3, load overflow only. Each chain deployment calls its backend directly (`api_base: http://qwen3.8-solo:8000/v1`, `anthropic/…`) — never point one at a LiteLLM alias (it recurses and inherits that alias's `fallbacks: → claude-sonnet-5`). Chain deployments are **copies** of the standalone aliases: change an alias's settings → change every chain copy (timeouts excepted — chains carry their own). `LITELLM.md § Changing a chain`, `§ Adding a chain`.
- **Chains have no `fallbacks` entry.** A failed order is retried at the next order in-group; `router_settings.model_group_retry_policy: {TimeoutErrorRetries: 0}` on the four chains sends a timeout straight to the next order. Don't use `allowed_fails_policy` (switches every deployment to legacy cooldown).
- **`auto` is single-pass.** It is `router_settings.model_group_alias: {auto: local-private}` — no `model_list` entry, no `fallbacks` / `context_window_fallbacks` / retry-policy entry (looked up by model group, they would never apply after the rewrite), `hidden` unset (Open WebUI lists it). The pre-call hook still sees `"auto"`, awaits `POST /decide`, rewrites `data["model"]` to the returned chain, and LiteLLM streams that chain in the same pass. Only `auto` is decided; a request naming a chain is served as asked. `/v1/messages` to `auto` is routed too. One `auto` turn = one chain request: no fan-out, no quality escalation to Claude.
- **The stash, not `data["model"]`.** The footer and `/observe` read `zeo_route_policy` (`requested_model`, `route`, `source: engine | fallback:<why>`, `decision_id`) in the proxy's metadata dict — `data["metadata"]`, or `data["litellm_metadata"]` on `/v1/messages`. `data["model"]` is the chain by then. Neither dict reaches the upstream.
- **`local-code` differs only per deployment:** one coding `litellm_system_prompt` (YAML anchor `&code_system_prompt` reused on all three orders), `reasoning_effort: high` on qwen / `reasoning_strength: xhigh` on muse, `max_tokens: 32768`. **Never put a `Reasoning strength:` line in that prompt** — Muse Glimmer's template would let it override the kwarg. `LITELLM.md § local-code: what it adds`.
- **Client parameters replace, never merge.** A client `max_tokens` replaces the deployment's; a request `extra_body` replaces the deployment's whole `extra_body` (`top_k` included); a top-level `chat_template_kwargs` replaces `extra_body.chat_template_kwargs`. The overflow hook's `/tokenize` body follows the same precedence.
- **The overflow hook** (`hooks/overflow/`, run from `Handler.async_filter_deployments`, before LiteLLM's pre-call context check and order filter): first **context fit** (exact vLLM `/tokenize` count of `messages` + `tools` + merged `litellm_system_prompt` + the one `chat_template_kwargs` LiteLLM sends; a deployment that does not fit is hard-dropped as `too-long`), then drops local backends **busy** (`vllm:num_requests_waiting` > 0 for `OVERFLOW_BUSY_AFTER_S`) or **down** (probe failed). It must: never drop a deployment without an `api_base` (Claude); never empty a group (busy → keep them and queue; all down → list unchanged — what keeps `local-private` local); ignore data older than 5 polls; **never throw** (LiteLLM re-raises a filter exception and fails the request). Nothing local fits → a by-name Claude chain keeps only Claude, but `local-private` and any request the client sent as `auto` keep their locals so vLLM refuses: length never sends `auto` to Claude. LiteLLM's own `enable_pre_call_checks` (tiktoken over `messages` only) is just the backstop. `LITELLM.md § The overflow hook`.
- **The shim** (`overflow.py`, mounted at `/app/overflow.py`, loaded by `get_instance_fn` via `spec_from_file_location`, never in `sys.modules`): only puts its dir first on `sys.path`, imports `hooks` normally, **removes that entry again** (the proxy already appends `/app`; leaving it first lets `/app/*` shadow installed packages) and builds `handler`. **No logic and no `@dataclass` in the shim** (relative imports fail there; `@dataclass` crashes proxy start). Inside `hooks/` both are fine. Every env read is in `hooks/settings.py`; the package layout is in `hooks/__init__.py`.
- **The leaf-class rule.** All five hooks (`async_filter_deployments`, `async_pre_call_hook`, `async_post_call_success_hook`, `async_post_call_streaming_iterator_hook`, `async_post_call_failure_hook`) stay in `Handler`'s own class body (`hooks/handler.py`) and delegate to `OverflowFilter`, `AutoFooter` / `FooterStream`, `PolicyClient`. The proxy activates the streaming-iterator and pre-call hooks only when they are in the leaf class's `__dict__`; a hook moved to a mixin or component silently never runs. The pre-call hook runs `AutoFooter.strip_incoming`, then `PolicyClient.route`.
- **Hook imports.** The container is upstream plus mounts: hooks may import only the stdlib, `litellm`, `yaml`, `httpx` and mounted `common` parts. `unit-tests/litellm/test_hook_package.py` enforces it; `test_overflow.py` loads the shim through LiteLLM's own `get_instance_fn`.
- **The `auto` footer** (`hooks/footer/`, `AUTO_FOOTER_ENABLED`) only on requests the client sent as `auto`, derived from `data["deployment"]`; skips tool calls, `response_format`, non-OpenAI shapes (`/v1/messages`) and Open WebUI background tasks; strips earlier footers from incoming assistant messages; never throws.
- **Applying a change:** `make up litellm` — the swap hash covers `litellm_config.yaml`, `overflow.py`, `hooks/` and the mounted `common` part, so an edit deploys with no downtime. Don't `docker restart litellm` after editing a single-file mount. Hook `OVERFLOW_*` / `ROUTE_POLICY_*` / `AUTO_FOOTER_ENABLED` changes are `.env` + `make up litellm`.
- **Prometheus** lives here but scrapes every stack (`prometheus.yml`: `litellm`, `classifier`, `detector`, `route-policy`, `signals`, `edge`). It is recreate-class with a single-file bind mount: a new or changed scrape job needs `docker restart prometheus`. Its `/metrics` key is a virtual key allowed only `/metrics` — never turn off `require_auth_for_metrics_endpoint` (the tunnel makes `/metrics` public). `LITELLM.md § Prometheus scrape key`, `§ Prometheus scrape jobs`.
- **Pass-throughs** (`/v1/classifier`, `/v1/detector`, `/v1/madlad`, `/v1/interceptor`, `/v1/roofix`, `/v1/sandbox`, `/v1/route-policy`) must carry `auth: true` — a config-file pass-through without it forwards keyless requests, and none of those services checks a token. A virtual key also needs the route in `metadata.allowed_passthrough_routes` (inside `metadata`, never the top-level field). `LITELLM.md § Pass-through auth`.
- **Spills and spend.** `[overflow]` / `[route-policy]` lines in `make logs litellm`; the spend log's model group is the chain, its model the deployment. A `local-private` row with a Claude model must never exist.

## Cross-folder rules

Also in the root `CLAUDE.md` § Cross-folder rules — read the named entry there for the full picture.

- **Route invariants — two copies** — `hooks/routing/invariants.py` (allowed routes = the four chain aliases, `CHAIN_ROUTES`) must agree with `ai/route-policy/route_policy/engine/invariants.py`; `unit-tests/litellm/test_hook_invariants.py` runs both. A new chain also goes into `CHAIN_ROUTES`. (root `CLAUDE.md` § Cross-folder rules)
- **`/decide` / `/observe` contract** — `hooks/routing/policy_client.py` is the client; the key sets are pinned on the service side. `/observe` is fire-and-forget (≤ 64 in flight, `ROUTE_POLICY_TIMEOUT_S`); `/decide` is awaited under `asyncio.wait_for` (`ROUTE_POLICY_DECIDE_TIMEOUT_S`) because LiteLLM puts no timeout around a pre-call hook. (root `CLAUDE.md` § Cross-folder rules)
- **`local-private` is where every failure ends** — no Claude deployment, no `fallbacks` / `context_window_fallbacks` entry (a loud comment in `litellm_config.yaml` says so). Every unrouted `auto` turn (timeout, non-200, bad JSON, `apply: false`, client off, the alias) lands there. The concrete aliases keep `fallbacks: → claude-sonnet-5` (re-read per hop), so nothing may route PII to them directly. (root `CLAUDE.md` § Cross-folder rules)
- **Open WebUI feeds routing** — the hook reads `X-OpenWebUI-Chat-Id` / `-Message-Id` / `-User-Id` for the service's turn pin; `background_task` is `hooks/footer/render.py::is_openwebui_task(data)` (Open WebUI's default task prompts, non-streamed only). (root `CLAUDE.md` § Cross-folder rules)
- **Timeout ladder** — chain deployments set both `stream_timeout` and `timeout`: 240 s local, 300 s Claude, per read; Open WebUI's 900 s total sits outside; `unit-tests/litellm/test_timeouts.py` enforces it. (root `CLAUDE.md` § Cross-folder rules)
- **Local vLLM slots** — `qwen3.8-solo` 3 sequences, `muse-glimmer` 8 of which the classifier takes ≤ 6; a busy queue is what spills chat to the next order and Claude. When `qwen3.8` runs on `muse-glimmer`'s GPU pair, `muse-glimmer` reads as down and chains degrade to `qwen3.8-solo`. `qwen3.6`, `qwen3.8`, `qwen3.8-flash`, `glm5.2` are in no chain; `glm5.3-flash` stays out on purpose. (root `CLAUDE.md` § Cross-folder rules)
- **Context windows** — `model_info.max_input_tokens` = vLLM `--max-model-len` − the deployment's `max_tokens`, per deployment (`LITELLM.md § Changing a chain`). (root `CLAUDE.md` § Cross-folder rules)
- **`common` inside LiteLLM** — `common.conversation` is bind-mounted at `/app/common/conversation` (with `common/__init__.py`); it must stay stdlib-only, and a new `common.<x>` import needs its own mount line. (root `CLAUDE.md` § Cross-folder rules)
- **LiteLLM pass-throughs carry the auth** — the seven `pass_through_endpoints` (Rules above) front services that check no token; each keeps `auth: true`. (root `CLAUDE.md` § Cross-folder rules)
- **Swap-class services publish through the edge** — `litellm` has no `container_name` / `ports:`; the edge's `listen litellm` publishes 4001 and TLS 443, with the per-key limit (`EDGE_LITELLM_MAX_CONCURRENT_PER_KEY`). Open WebUI, n8n and roofix call `litellm:4000` directly. (root `CLAUDE.md` § Cross-folder rules, § Deploys (`make up`))
- **Deploy order across stacks** — route-policy before `make up litellm` when the contract grows (until the service answers, every `auto` turn goes to `local-private`); `docker restart prometheus` after another stack adds a scrape job. (root `CLAUDE.md` § Cross-folder rules)
- **`api.zeoenergy.com` is split-horizon** — the cloudflared tunnel sends the public name straight to `litellm:4000` (why `/metrics` must stay authenticated); the LAN reaches the edge on 443. (root `CLAUDE.md` § Cross-folder rules)

## Env vars

One line each; full detail in `.env.example` (LiteLLM block) and the `LITELLM.md` sections named. All are passed through the compose `environment:`; apply with `make up litellm`.

- `OVERFLOW_BUSY_AFTER_S` (`2`) — seconds `num_requests_waiting` > 0 before a backend is busy and dropped from chains; lower spills (to Claude, with both locals busy) sooner. `§ Tuning`.
- `OVERFLOW_IDLE_AFTER_S` (`5`) — seconds the queue stays at 0 before a busy backend is used again; keep it above `OVERFLOW_BUSY_AFTER_S` (flapping).
- `OVERFLOW_POLL_INTERVAL_S` / `OVERFLOW_PROBE_TIMEOUT_S` (`1` / `0.75`) — `/metrics` probe cadence (floor 0.2) and per-probe timeout; a failed probe = down; keep the timeout below the interval.
- `OVERFLOW_TOKENIZE_MIN_FRACTION` (`0.6`) — context fit asks `/tokenize` only when the high estimate reaches this fraction of a deployment's `max_input_tokens`; `0` asks on every chain request. `§ The overflow hook`.
- `OVERFLOW_TOKENIZE_CHARS_PER_TOKEN` (`2.5`) — divisor of that estimate; deliberately low so it runs high — raising it skips prompts that should be measured. Floor 0.5.
- `OVERFLOW_TOKENIZE_TIMEOUT_S` (`5`) — wall-clock limit on one `/tokenize`; past it (or any failure) the deployment is kept. Floor 0.1.
- `AUTO_FOOTER_ENABLED` (`true`) — the `*<model> · <chain>*` footer on `auto` answers, and the stripping of old ones; routing does not depend on it. Also set Open WebUI's Task Model to a non-`auto` model. `LITELLM.md` § The `auto` footer.
- `ROUTE_POLICY_ENABLED` (`true`) — the route-policy client. `false` is not "route another way": every `auto` turn goes to `local-private` as a logged fallback. `LITELLM.md` § Route policy: single-pass `auto`.
- `ROUTE_POLICY_URL` (`http://route-policy:8000`) — the service by Docker DNS, no auth; empty = disabled (as above).
- `ROUTE_POLICY_DECIDE_TIMEOUT_S` (`0.25`, floor 0.05) — budget of the awaited `/decide`, added to every `auto` turn's latency; past it → `local-private`. Raising it trades latency for fewer private fallbacks.
- `ROUTE_POLICY_TIMEOUT_S` (`2`, floor 0.1) — one background `/observe`; bounds a hung service's hold on the 64 in-flight slots, never the request.
