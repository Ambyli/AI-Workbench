# ai/route-policy

The route-policy engine (ZT-471): a **ruleset** of **evaluators** votes on which LiteLLM chain alias an `auto` turn uses, a **combiner** (`priority` / `weighted`) picks one, the **invariants** have the last word, and every decision, vote and outcome is logged to `route-policy-db` (Trino: `postgres_route_policy`). `route-policy` (FastAPI, swap-class, `route-policy:8000`) + `route-policy-db` (Postgres 17, recreate-class), [`docker-compose.route-policy.yml`](docker-compose.route-policy.yml). Guide: [`ROUTE_POLICY.md`](ROUTE_POLICY.md) (phase history, upgrade orders, schema, metrics); benchmark: [`bench/BENCH.md`](bench/BENCH.md). Tests: `unit-tests/route-policy/`, own pytest process (`ROUTE_POLICY.md § Tests`).

## Rules

- **What routes today.** `default` (version 3, `mode: enforce`, `pin: turn`) is the only ruleset that routes; `default-llm` and `default-signals` are **shadows** bound beside it (`bindings.yaml` `shadow:`) — decided and logged after the answer, never applied, so a shadow never changes routing. A binding's primary must be `mode: enforce`, every shadow slot `mode: shadow` (seeding refuses otherwise).
- **Routing rules live in rulesets, never env vars.** `rulesets/*.yaml` (+ `patterns/*.yaml` via `patterns_ref`, `examples/*.yaml` via `examples_ref`) are baked into the image and seeded at startup. Env vars are infrastructure only; the classifier's model / criteria / thresholds and the signal evaluators' model pins / thresholds / example sets are ruleset config.
- **Ruleset versions are immutable.** The content hash is over the resolved document (refs inlined, comments ignored); a stored id + version whose content differs **stops startup** (`SeedConflict`). Any edit — a description, a pattern, an example — means bumping `version`. A `patterns/*.yaml` file is content of `default`, `default-llm` AND `default-signals`: edit one, bump all three; `examples/routes.yaml` is content of `default-signals`.
- **A stored version needs no file — keep only the current ones baked in** (`default@3`, `default-llm@3`, `default-signals@1`). Old versions compile from the database. An old version's file would freeze the pattern files it hashes.
- **The `default` ruleset and its pattern files are the only copy of the routing rules** (the semantic router is gone). `priority`, first non-abstaining vote wins: `privacy` (`force` → `local-private`), `code-text`, `reasoning-text` (latest user message), `code-tools` (a sandbox / Open Terminal tool CALLED this exchange — offered tools never count), `sticky-code` (2-exchange `cooldown`), else `local-general`. Changing a pattern or the wiring = update `test_default_ruleset.py`'s expectations + bump the version (`ROUTE_POLICY.md § Rulesets` has the steps).
- **Patterns stay in the RE2 subset**: no lookaround, backreferences, atomic / possessive groups, `\Z`; regex keywords in YAML **single** quotes. Python `re` accepts more, so `test_default_ruleset.py` is the portability check. Matching is `common.keywordmatch` (Go-RE2 semantics).
- **The privacy rule is lexical.** A PII prompt naming no `privacy_kw` word lands on another chain and can overflow to Claude — widen `patterns/privacy.yaml` rather than trust it. `pii` (`default-signals`) is the measured fix, not yet promoted.
- **One route per turn (`pin: turn`).** Every `/decide` of one answer (same Open WebUI `chat_id` + `message_id`: tool rounds and the auto-continue nudge) keeps the route of the turn's first stored decision of that ruleset id; every evaluator still runs and is logged, the invariants run again on the pinned route, a **fresh `local-private` always beats the pin**, and later calls store `pinned_from` and enqueue no classification. No pin without both ids (Claude Code), for a background task, or on `/evaluate`. A shadow pins from its OWN shadow rows.
- **Background tasks** (`background_task` on `/decide`, optional, default `false`): decided and logged, never classified (`llm_classifier` abstains `background task`), never pinned, never pinning.
- **Invariants are enforced twice** (`route_policy/engine/invariants.py`, pure, stdlib-only, and the LiteLLM hook's copy): a requested `local-private` stays `local-private`; a route outside the ruleset's `routes` becomes the fail-safe with `apply: false`. A vote for an unlisted route is an evaluator error, never a route.
- **`observe` role**: evaluated and logged with its would-be route, ignored by both combiners (no score, force or veto). That is how a signal is measured without routing; promote by changing the `role` in a new version.
- **Nothing slow on `/decide`.** The pipeline is pure: the service prefetches everything first — verdict lookup, turn-pin read (both `config.DB_READ_BUDGET_S`, 0.1 s) and the ONE signals call (`ROUTE_POLICY_SIGNALS_BUDGET_S`) concurrently — via the `Evaluator` hooks `analysis_lookups` / `signal_requests` (default empty); `analysis_requests` and shadows run in ONE background task after the answer. LiteLLM gives `/decide` 0.25 s, so no database wait may hold it: the decision write is a shielded task awaited for at most `ROUTE_POLICY_DECISION_WRITE_BUDGET_S`, finished in the background past it, capped at `WRITES_MAX_IN_FLIGHT` (256, then dropped and counted), drained `WRITES_DRAIN_S` (5 s) at shutdown. Past a read budget: a stale snapshot, an abstain, a call decided afresh, or a `503` (→ the hook's `local-private`). `test_writes.py` / `test_shadows.py` cover it with a hung database.
- **Two signals-call rules.** Validation refuses two evaluators asking the same signals task with different parameters (one request carries each task once). Every signals status but `ok` / `partial` is an abstain — the sidecar down, slow or wrong never moves a turn; `pii` still forces from `common.pii`'s in-process patterns.
- **No message text is ever stored or logged.** Decisions keep ids, routes, votes, reasons (pattern indices, tool names, entity types, scores); `analyses` keeps a transcript HASH plus the winning criterion's reason (≤ 200 chars, CHECKed — the only model-written text). Every exception route-policy logs or stores (`evaluations.error`, a vote reason, a shadow error) is its **type name only** — a message can quote the conversation.
- **`llm_classifier` verdicts.** Keyed `input_key = sha256(fingerprint, render_transcript(..., upto_user=k))`, so tool rounds of one message share one classification and an edited message never reuses a verdict; read at `/decide` for messages n … n − `max_age_exchanges` in one query, so a verdict applies **from the next turn on**. The analysis queue is **in memory on purpose** (it holds transcripts; never `common.jobs`' Postgres queue). The criteria are in the fingerprint: changing them classifies from scratch.
- **The database is routing control.** A `bindings` row (re-read every `ROUTE_POLICY_BINDING_REFRESH_S`) or a new `rulesets` version decides every `auto` turn, PII included — override the dev-default `ROUTE_POLICY_DB_PASSWORD`, keep 5441 off untrusted networks. Startup needs the DB (migrations + seeding); once up, `/decide` decides from cache without it (unlogged).
- **Schema changes are new `route_policy/db/migrations/NNNN_*.sql` files.** Applied ones are recorded with their SHA-256; editing one stops startup (`MigrationChanged`). `outcomes` and `decisions.shadow_of` / `pinned_from` have no FK on purpose (writes may land in either order).
- **No auth on the service** (classifier posture): LAN access is `EDGE_ALLOWED_CIDRS` on 8027, or LiteLLM's `/v1/route-policy` pass-through (`auth: true`).
- **Swap-class**: the container is `route-policy-<hash>` — `make logs route-policy route-policy`, `make exec route-policy route-policy CMD='…'`, never `docker exec route-policy`. `route-policy-db` keeps its name.
- **Result shapes**: each evaluator type declares its `detail` with `@declares(OutputSpec(...))` beside its class, served by `GET /evaluator-types`, checked by `test_declarations.py`. A new type = module + one line in `evaluators/base.py::_DECLARING_MODULES` + test cases. Root `CLAUDE.md` § Result shapes declared beside the producer.
- **Promotion is a NEW `default` version**, never an edit, and only after the benchmark / Trino criteria in `ROUTE_POLICY.md § Promoting the classifier` / `§ Promoting the signals` pass.
- **Example sets are curated, PII-free, never real prompts or their embeddings**; ids are stable (never reuse a removed id). A test runs `common.pii` over every example.

## Cross-folder rules

Also in the root `CLAUDE.md` § Cross-folder rules — read the named entry there for the full picture.

- **Route invariants — two copies.** `route_policy/engine/invariants.py` ↔ `ai/litellm/hooks/routing/invariants.py`; `unit-tests/litellm/test_hook_invariants.py` runs both. Keep `enforce` / `fail_safe_route` / `PRIVATE_ROUTE` names and behaviour stable; change both together.
- **`/decide` / `/observe` contract.** `/decide` takes `{decision_id, requested_model, litellm_call_id, chat_id, message_id, user_id, key_alias, messages, tools, backends, background_task}` and returns exactly `{decision_id, route, mode, apply, ruleset, votes, scores, latency_ms}`; `/observe` returns 202. Idempotent on the hook-made `decision_id` (first write wins, a duplicate `/decide` replays). Key sets pinned by `test_pipeline.py` / `test_api.py` — change only together with `ai/litellm/hooks/routing/policy_client.py`; new request fields optional so route-policy deploys first.
- **`local-private` is where every failure ends.** The service's fail-safe route, the hook's fallback for anything not `apply: true`, never pinned away. A wrong answer here can never move a turn off `local-private`.
- **Open WebUI feeds routing.** Turn pins key on `X-OpenWebUI-Chat-Id` / `-Message-Id` (`OPENWEBUI_ENABLE_FORWARD_USER_INFO_HEADERS` + patch `0005`); patch `0004`'s nudge is an extra user message under the same message id; `background_task` comes from the hook's `is_openwebui_task`. Recommend Task Model = `local-private`.
- **`qwen3.5-4b` sizing.** `topic-llm`'s `history.max_chars` must stay ≤ the classifier entry's `text_char_budget` (12000); `ROUTE_POLICY_ANALYSIS_CONCURRENCY` (2) matches its `max_concurrent: 2`.
- **Signals contract.** `common.signals` is the wire format of both the sidecar and this client — change together. A model change in `ai/signals/models.yaml` needs a new ruleset version for every evaluator pinning that model id (they abstain `model mismatch` until bound).
- **Classifier as route-policy's model runner.** `route_policy/analysis/classifier_client.py` uses `POST /assess`, `GET /models`, `GET` / `DELETE /jobs/{id}` (always deletes, after copying usage into `analyses`); submits only to a model that is `authenticated: false`, `available: true` and resolves to private addresses (`not_local` otherwise — a stopped container too). A classifier API change breaks it; route jobs share the classifier's FIFO with document jobs.
- **Trino reads other stacks' Postgres.** `db-init/10-trino-reader.sh` makes `trino_reader` on the FIRST start of an empty volume (password `ROUTE_POLICY_TRINO_READER_PASSWORD`, also in `trino-coordinator`'s env); catalog `ai/trino/catalogs/postgres_route_policy.properties`.
- **`common` inside LiteLLM.** Route-policy reads conversations through `common.conversation` (`user_text` strips Open WebUI's RAG block, `split_exchanges`, `called_tool_names`, `render_transcript`, `user_texts`, `tool_results`), keyword rules through `common.keywordmatch`, PII through `common.pii`, locality through `common.net`, the sidecar through `common.signals` — a change in any of them changes routing (and `render_transcript` changes verdict keys). `common.conversation` is also mounted into LiteLLM, so it stays stdlib-only.
- **LiteLLM pass-throughs carry the auth.** The service checks no token; LiteLLM's `/v1/route-policy` pass-through has `auth: true` — never drop it.
- **Swap-class services publish through the edge.** `route-policy` has no `ports:` / `container_name`; 8027 is the edge's `listen route-policy`. Root `CLAUDE.md` § Deploys (`make up`).
- **Deploy order across stacks.** `make up edge` before the first `make up route-policy`; `signals` before `route-policy` (startup warms the example sets); route-policy before `make up litellm` when the contract grows; `make up trino trino-coordinator` after the catalog env changes; `docker restart prometheus` for its scrape job; `docker restart classifier` after its `models.yaml` changes. Staged upgrades: `ROUTE_POLICY.md § Deploying` and its `§ Upgrading …` subsections.

## Env vars

One line each; full detail in `.env.example` and `ROUTE_POLICY.md § Configuration`. `unit-tests/route-policy/test_wiring.py` checks the ports and `ROUTE_POLICY_TRINO_READER_PASSWORD` are listed here — keep them. LiteLLM's client vars (`ROUTE_POLICY_ENABLED`, `_URL`, `_TIMEOUT_S`, `_DECIDE_TIMEOUT_S`) are in `ai/litellm/CLAUDE.md`.

- `PORT_ROUTE_POLICY` (`8027`) — LAN port, published by `ai/edge`, `EDGE_ALLOWED_CIDRS`-limited; `make up edge` first.
- `PORT_ROUTE_POLICY_DB` (`5441`) — `route-policy-db` host port; Postgres group of the `PORT REGISTRY` (not `5434`, a host Postgres). Root § Env vars and the PORT REGISTRY.
- `ROUTE_POLICY_DB_USER` / `_PASSWORD` / `_NAME` (`route_policy` × 3) — DB credentials; override the password (the DB is routing control). `_HOST` / `_PORT` are fixed in compose.
- `ROUTE_POLICY_TRINO_READER_PASSWORD` (empty) — `trino_reader` password; set BEFORE the first start; empty skips the role (only Trino breaks); retrofit in `ROUTE_POLICY.md § Operations`. Real secret.
- `ROUTE_POLICY_DB_POOL_MAX` (`10`) / `ROUTE_POLICY_BINDING_REFRESH_S` (`10`) — pool ceiling; max age of the binding snapshot.
- `ROUTE_POLICY_DECISION_WRITE_BUDGET_S` (`0.05`) — how long `/decide` / `/observe` wait for their row; keep well under LiteLLM's 0.25 s decide timeout.
- `ROUTE_POLICY_CLASSIFIER_URL` (`http://classifier:8000`) — classifier for background classifications; not a `depends_on`; empty (outside compose only) = every `llm_classifier` abstains.
- `ROUTE_POLICY_CLASSIFY_TIMEOUT_S` (`180`) / `ROUTE_POLICY_CLASSIFY_POLL_S` (`1`) — one classification's limit (then cancel + DELETE, `timeout`); poll interval. Look at `analyses.queue_ms` before raising the timeout.
- `ROUTE_POLICY_ANALYSIS_QUEUE_MAX` (`64`) / `ROUTE_POLICY_ANALYSIS_CONCURRENCY` (`2`) — waiting requests (then dropped, `queue_full`); workers = route jobs open on the classifier (keeps its FIFO free for document jobs).
- `ROUTE_POLICY_SIGNALS_URL` (`http://signals:8000`) — the signals sidecar; text is sent only to a host resolving to the box's networks; empty (outside compose only) = signal evaluators abstain, `pii` uses patterns.
- `ROUTE_POLICY_SIGNALS_BUDGET_S` (`0.1`, floor `0.04`) — one decision's wait for its signals call; sidecar told 20 ms less; at or below `DB_READ_BUDGET_S` it adds nothing to `/decide`'s worst case. Check `SIGNALS_CPUSET` before raising it.
