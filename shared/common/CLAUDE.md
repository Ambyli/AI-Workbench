# shared/common — the `common` package

Shared Python for every project in the uv workspace (`common = { workspace = true }`). The reuse rule (what must live here) is root `CLAUDE.md` § Shared Python code (`shared/common`). Overview: [`README.md`](README.md). Tests: `shared/common/tests/` (`uv run --no-sync python -m pytest shared/common/tests -q -p no:cacheprovider`; `test_jobs_postgres.py` skips without `TEST_POSTGRES_DSN`).

## Rules

- New capability: `src/common/<name>/`, public API from its `__init__.py`, tests under `tests/`. Heavy deps go in an optional extra (`documents`, `net`, `signals`, …) and are imported lazily, so the pure parts stay stdlib-importable; consumers need no pyproject change unless a new external dep appears.
- Stdlib-only parts stay stdlib-only: `conversation`, `keywordmatch`, `logprobs`, `pii`, `textops`, `signals.wire`, `documents.detect` / `svg` / `textmatch`, `net` (except `fetch_url`), `jobs.progress`, `vision` (except the raster renderers).
- **Callers' behaviour lives here.** `conversation`, `keywordmatch`, `pii`, `net.check_locality` and `signals` decide what route-policy routes; `textops` is the sandbox's file-tool contract; `jobs`, `documents`, `vision` carry the classifier. A change here also runs the consumers' suites (`unit-tests/route-policy`, `unit-tests/litellm`, `unit-tests/signals`, `unit-tests/sandbox`, `unit-tests/classifier`).

## Cross-folder rules

Also in the root `CLAUDE.md` § Cross-folder rules — read the named entry there for the full picture.
- **`common` inside LiteLLM** — `common.conversation` is bind-mounted at `/app/common/conversation` (+ `common/__init__.py`) into the LiteLLM container, which does not install `common`: it must stay stdlib-only, and a new `common.<x>` import in `ai/litellm/hooks/` needs its own mount line (`unit-tests/litellm/test_hook_package.py`).
- **Signals contract** — `common.signals` is both the `signals` sidecar's wire format and route-policy's client; a field, status or cap change ships to both together.
- **`cdp_interceptor` traps** — below; they bite `widget/` and `ai/interceptor/` alike (the interceptor image bakes `shared/common`: a change there is `make build interceptor && make up interceptor`).
- **Smaller couplings** — `common.textops` is the sandbox's file-tool edit contract (`ai/sandbox`): run `shared/common/tests/test_textops.py` and `unit-tests/sandbox` after changing it.

## `cdp_interceptor` traps

- CDP needs a running Chrome with `--remote-debugging-port`; `launcher.py` starts it itself (no Selenium). One browser per profile dir — the singleton lock; `clear_singleton_locks()` cleans a crashed Chrome's.
- The 4 s sleep at the top of `InterceptorClient._loop()` (`client.py`) waits for Chrome's tab and debug endpoint; removing it makes start-up connections fail.
- `interceptor.js` is read once at import (`_BUNDLED_INTERCEPTOR_JS`) — editing it needs a process restart — and is injected **verbatim** as a CDP parameter: never reformat it.
- It reads bodies through `response.clone()` (without it the page gets an empty body) and guards re-injection with `window._fetchInterceptorActive` (also the `run_actions` readiness gate). Keep both.
- `InterceptorClient.is_available()` is false without `requests` + `websocket-client`; consumers then silently disable the feature.
Guide: [`src/common/cdp_interceptor/README.md`](src/common/cdp_interceptor/README.md).

## Subpackages

- `common.cdp_interceptor` — Chrome DevTools Protocol interceptor (used by `interceptor`, `widget`).
- `common.conversation` — reading an OpenAI-style chat-completions history: `message_text` (a string, or a multimodal list's `text` parts), `user_text` / `strip_openwebui_rag` (what the USER typed: Open WebUI v0.11.4 rewrites the latest user message on a request with retrieved sources — attached files, the pages a web search / fetch tool returned — as its RAG template, `### Task: … <context>…</context>`, then the user's words; these keep only the words after the LAST `</context>\n\n`, and `split_exchanges` / `render_transcript` read user text through them, so route-policy's keyword rules and classifier transcript never read Open WebUI's instructions or a fetched page — the template's "the proposed method …" example tripped `code_kw` on every fetch round), `split_exchanges` (one exchange per user message: its text plus every round and tool result after it), `called_tool_names` (tools actually CALLED, most recent first — OpenAI `tool_calls` / `function_call`, Anthropic `tool_use`, named tool results; offered `tools` are never read), `user_message_count` (user messages = exchanges), `user_texts` (`user_text` of EVERY user message, oldest first, exactly one entry each — `""` for one without text — so entry k-1 is user message k), `tool_results` (every tool RESULT, oldest first, as `(message index, tool name, text)`: OpenAI `tool` / legacy `function` messages and Anthropic `tool_result` blocks, each named by its own `name` or by the call it answers — `tool_call_id` → an assistant's `tool_calls[].id`, `tool_use_id` → a `tool_use` block's `id`; no RAG stripping, it is not user text) and `render_transcript(messages, *, exchanges, max_chars, upto_user=None)` — the conversation up to its k-th user message as `User:` / `Assistant:` / `[tool: <name>]` text (tool results and non-text parts dropped), the last N exchanges within a character budget (oldest cut first, the latest user message always kept), deterministic and unchanged as the conversation continues — what route-policy's `llm_classifier` sends to the classifier and hashes into its verdict key, and what its benchmark renders decision points with. Stdlib only, never raises on junk (`render_transcript` raises `ValueError` only for a bad argument). Used by `route-policy` (the `tool_calls` and `cooldown` evaluators; the `llm_classifier` and `bench/`; the signal evaluators, which send `user_texts` and the selected `tool_results` to the `signals` sidecar as `u<k>` / `t<k>`) and by the LiteLLM hooks (the `auto` footer's background-task detection reads `message_text`; bind-mounted, see above).
- `common.documents` — document loading + OCR + text matching (used by `classifier`; `detector` uses `ensure_image_support`). `detect_kind` identifies JPEG/PNG/HEIC/HEIF/AVIF/PDF/SVG/TXT/DOCX by magic bytes and structure (never by filename or Content-Type; an SVG — UTF-8 XML whose first element is `<svg>` — is checked before the txt fallback; legacy `.doc` gets its own "convert to .docx" error, gzip / `.svgz` a "decompress to .svg" one, and an MP4 / MOV — an ISO-BMFF `ftyp` box with no image brand, e.g. a Live Photo's video — a "video is not supported" one); `image_format` names the format inside the `image` kind (`jpeg` / `png` by magic bytes, `heic` / `avif` / `heif` by the `ftyp` brands, bounded by the box and the buffer) and `guess_content_type` maps it through `IMAGE_CONTENT_TYPES`; `ensure_image_support` registers pillow-heif's Pillow opener once per process and raises a named "needs pillow-heif" / "needs Pillow ≥ 11.3 with AVIF" error when this process cannot decode the format (`available_image_formats()` is the live list) — every decoder calls it before `Image.open`, and a HEIF's container rotation is applied exactly once (pillow-heif applies `irot` / `imir` and resets the EXIF tag; Pillow's AVIF plugin reports them AS the EXIF tag), pinned against an EXIF-oriented JPEG for all eight orientations; `load_document` turns bytes into a `Document` of `Page`s that carry an image, a text layer, or both (PDF: native text + a render per page at a given DPI, capped at `max_pages`; SVG: one page rendered by MuPDF the same way, its `<text>` the native text, the render capped at `max_render_pixels` (`DEFAULT_MAX_RENDER_PIXELS`, 25 MP), and one `Document.warnings` line per external reference it did not draw — MuPDF fetches nothing, pinned by a no-fetch regression test; DOCX: paragraphs and table cells in document order; the image decoder is injectable so a service keeps its own EXIF handling), and `pdf_page_count` / `pdf_page_size` / `svg_page_size` read a PDF's page count / a page's (or an SVG's) render size in pixels without rendering; `svg.py` (stdlib) has `looks_like_svg`, and `find_external_refs` + `replace_refs`, which find an SVG's external `<image>` / `<feImage>` / `<use>` hrefs by byte span and rewrite them — how a service inlines an image it fetched itself; `pdf_text_regions(..., filetype="svg")` boxes SVG text hits; `apply_ocr` fills missing text via any `OCREngine` (`RapidOCREngine` bundles RapidOCR/PP-OCRv6 on ONNXRuntime) in `auto` / `always` / `never` modes, and `recognize_text_layer` does the same WITHOUT mutating the page — it returns a `TextLayer`, so several OCR settings can coexist on one document (`with_text_layers` builds an image-sharing view, `match_text_layers` searches one); `match_text` searches it in `contains` / `exact` / `regex` / `fuzzy` modes — fuzzy being the one that survives OCR noise. Heavy deps (`pymupdf`, `python-docx`, `rapidocr`, `onnxruntime`, `pillow` ≥ 11.3, `pillow-heif`, `numpy`) live in the optional `documents` extra and are imported lazily, so `detect`, `svg` and `textmatch` stay pure-stdlib importable.
- `common.env` — walk-up `.env` loader.
- `common.keywordmatch` — keyword rules with Go RE2's semantics (those of vLLM Semantic Router v0.3.0's `keyword_classifier_regex.go`, which the rules were first written for): `compile_keyword_rule(rule)` → `KeywordRule(operator, patterns).matches(text)` — `method: regex` uses each keyword as a pattern, otherwise a whole literal word (`\b` + escaped + `\b`, quirks included), `case_sensitive: false` ignores case, ASCII `\b`/`\w` as in RE2, `OR` / `AND` / `NOR`; raises `ValueError` on a bad rule. No YAML here — the caller loads the rule. Python `re` accepts more than RE2, so the owner of the rules checks the RE2 subset (`unit-tests/route-policy/test_default_ruleset.py` for `ai/route-policy/rulesets/patterns/`). Stdlib only. Used by `route-policy` (its `regex_text` evaluator).
- `common.logging_setup` — CSV audit logger + stdlib configuration.
- `common.logprobs` — what an OpenAI-style server's token log-probabilities say about ONE integer field of a JSON answer: `int_field_distribution(entries, key, lo, hi, *, content=None, top_key="top_logprobs", number_tokens="auto")` → `Distribution | None` (`probs` value → p renormalised over the numeric mass, `unresolved` `[Unresolved(values, mass)]`, `coverage` = the numeric mass before renormalising, `sampled`; `mass()` — a lower bound —, `expected()`, `entropy_bits()`, `certainty()`, `even_split()`), `from_samples(values, lo, hi)` (the empirical distribution of n sampled answers, coverage 1.0) and `resolve_path(data, "choices.0.logprobs.content")`. The answer is anchored at the last match of `content`'s start and the LAST `"<key>":` after it is read, so a reasoning prefix in the stream (vLLM includes reasoning tokens) and a decoy `"score"` in it are skipped; a whole-number tokenizer (`10` one token) and a split-digit one (`1`, `0`: the sampled first digit's continuation is read from the next position) are both exact, and a NON-sampled strict prefix (`1` when 10 is in range) under split digits is `unresolved`, never guessed; `number_tokens` pins the tokenizer, and a pin the stream contradicts is a WARNING with the stream winning. Values clamp into `[lo, hi]`. Stdlib only, never raises on a garbled stream. Used by `classifier` (`llm/client.py` → `llm/confidence.py`, per `models.yaml` `confidence.method`).
- `common.net` — the SSRF guard for caller-supplied URLs (`validate_url`, `BlockedURLError`, `DEFAULT_BLOCKED_NETWORKS`), and `fetch_url` — the fetch that always runs it first, refuses redirects (`FetchError`, with a short `.reason`), streams the body against `max_bytes`, and takes an optional wall-clock `deadline` (httpx, lazily imported — the `net` extra). The classifier's document-URL input and its SVG image inliner use `fetch_url`; moving the detector's own fetch onto it is a follow-up. Deliberately framework-free (it raises, it does not return an `HTTPException`), so each service maps the refusal to its own error shape; a blocklist that drifts between two services is worse than none, which is why it is here. The same list answers the opposite question: `locality_problem(host, resolver=None)` (`None` when EVERY address the host resolves to — `getaddrinfo`, so IPv6 and every address of a multi-homed name — is private / loopback / link-local, else a short reason naming the host and the rule, never an address; an unresolvable host fails, since Docker DNS answers only for running containers; never raises), `check_locality` (→ `LocalityVerdict(problem, resolved)`, so a caller caches an unresolved verdict only briefly), `resolves_locally` and `resolve_host` — the guarantee a service needs before it sends conversation text to another box-internal service, used by `common.signals`' client (route-policy's classifier client implements the same rule). Stdlib, blocking: an async caller runs it in a thread and caches the verdict. Used by `classifier`, `detector`, `route-policy`.
- `common.pii` — structured personal data found with no model: `find(text)` → `[PiiMatch(type, start, end, rule)]` (text order, non-overlapping) and `counts(text)` → `{type: n}`, plus the shared entity vocabulary `ENTITY_TYPES` (`email`, `phone`, `street_address`, `gov_id`, `card_number`, `bank_account`, `account_number`, `date_of_birth`, `person`, `location`, `other`), `SENSITIVE_TYPES` (the first seven, which force on their own), `PATTERN_TYPES` and the validators (`luhn_valid`, `card_iin_valid`, `iban_valid`, `aba_valid`, `ssn_valid`, `itin_valid`). A regex finds the candidate, a checksum or a context word decides: plain and obfuscated emails (`jenna dot price at gmail dot com`), NANP / `+` international phones, US street addresses + the Utah grid (`77 N 400 E`) + PO boxes + Latin-American streets, SSNs / ITINs in range, CURPs and ids after their word, Luhn cards with an issuer prefix, IBAN mod-97, ABA-checksummed routing numbers, account numbers after their word, a date of birth only after its word. Precision over recall (an order number, a version, `555 times 147`, `port 8080` stay alone); `person` / `location` have no shape and come only from the sidecar's NER. Stdlib only, pure, never raises (a recogniser that raises on a text loses only its own matches there; a letter class a lookup is keyed by is ASCII-only, because `re.I` folds `ſ` / `K` / `ı` / `İ` onto ASCII letters — `77 N 400 ſ` once raised `KeyError('ſ')`), linear (100 KB in < 20 ms is a test); spans never leave the caller — what it reports or stores is `counts`. Used by `route-policy` (the `pii` evaluator, in-process on every call, so it forces while the sidecar is down) and by the `signals` sidecar (its NER labels map onto the same vocabulary); built for later redaction anywhere.
- `common.processed_store` — Gmail message-id dedup cache (used by `roofix`).
- `common.signals` — the `signals` sidecar's wire format and its client, so both sides agree once. `wire` (stdlib): `SignalsRequest(texts, tasks, request_id, deadline_ms)` / `SignalsResponse` and their parts (`TextItem`, `TaskRequest`, `TaskResult`, the per-task features `PiiFeatures` / `NearestFeatures` / `InjectionFeatures` / `LanguageFeatures`, `Example` / `ExampleSet`) as frozen, self-validating dataclasses with `to_json` / strict `from_json` (`WireError` names the field and rule, never a value), the `TASKS` / `STATUSES` / `TASK_MODELS` vocabularies, the request caps (`MAX_TEXT_CHARS` 20,000, `MAX_REQUEST_CHARS` 200,000, `MAX_TEXTS` 64, `MAX_EXAMPLES` 1,000, …, `cap_problem()`), and `fingerprint_examples(items, model)` (the example-set cache key). `client`: `SignalsClient(base_url, *, models_ttl_s=60, unresolved_ttl_s=2)` — `await fetch(request, *, budget_s)` / `warm(examples, …)` return a `SignalsOutcome(status ∈ ok | timeout | error | unavailable | not_local, response, ms, error)` and **never raise** (only a cancellation of the caller propagates); the locality guard (`common.net.check_locality`, cached `models_ttl_s`, a host that did not resolve only `unresolved_ttl_s`, so a restarted sidecar is reached again within seconds) sends no text to a host that resolves off the box's networks; httpx is imported lazily (the `signals` extra). Never text or spans in an answer, an error, or anything the client returns. Used by `route-policy` (the signal evaluators' one call per decision) and the `signals` sidecar (it parses requests and builds answers with these classes).
- `common.textops` — numbered views, exact-string edits and UTF-8-safe truncation for tools that let a model read and change text files, following Claude Code's file-tool contract: `number_lines` / `split_lines` (`cat -n` style, `<number><TAB><line>`), `apply_edit` (`old_string` → `new_string`, unique match or `replace_all`, CRLF and trailing newline preserved, a numbered snippet of the change) raising `FileOpError(kind, message, **extra)` — `not_found` carries the closest region of the file (`closest_region`, difflib over whitespace-stripped lines), `line_number_prefix` names a pasted prefix, `multiple_matches` lists the lines — plus `rewrite_guard` (is a whole-file write over an existing file mostly a re-send? thresholds are the caller's) and `utf8_tail` / `decode_utf8_prefix` for byte caps that never split a character. Stdlib only. Used by `sandbox` (`read_file` / `edit_file` / `write_files` MCP tools, `exec` output tail).
- `common.trino` — `TrinoClient` / `TrinoQueryError`, a thin wrapper over the Trino driver (optional dep `trino`). Rejects everything except `SELECT` / `WITH` / `SHOW` / `DESCRIBE` / `EXPLAIN` unless `allow_writes=True` (only `ai/trino/bin/init_warehouse.py`); clamps rows (spliced `LIMIT`) and runtime. Used by `ai/trino/mcp/server.py` and `init_warehouse.py`.
- `common.vision` — say *where*, then draw it: `Region` / `PageGeometry` (regions are always in ORIGINAL page pixels) and the transforms between the working image, the page, PDF points, and the 0–1000 grid a vision model answers on; `slugify_criterion` + a stable colour-per-criterion / stroke-per-source policy; `render_svg` / `render_png_layer` / `render_preview`; and `ArtifactStore`, one directory per job with a manifest, a byte cap with a defined drop order, a zip view, and a sweeper that prunes job rows as well as files. Pure stdlib except the two raster renderers, which import Pillow at call time — nothing here needs OpenCV or numpy. `normalize_region` + `center_distance` compare boxes on two DIFFERENT pages (each as a fraction of its own page — the classifier's reference position check), and the `"manual"` region source (heavy solid stroke) marks a region a person supplied rather than one a producer found. Used by `classifier`; built to be adopted by the interceptor's screenshots.
- `common.jobs` — id-addressable job tracking with three backends: `InMemoryRegistry` (sync, ephemeral — `interceptor`), `SqliteRegistry` (async, `aiosqlite`, persistent — no current service consumer), and `PostgresRegistry` (async, `asyncpg`, persistent, JSONB metadata, real connection pool — `sandbox`, which lets it own its pool (`dsn=`), and `classifier`, which hands it the one pool its three stores share (`pool=`, never closed by the registry) and asks for a `JSON` result column (`result_type="json"` — JSONB sorts object keys)). Both persistent backends expose `expired_job_ids(cutoff, phases, *, limit)`, the bounded query `common.vision.ArtifactStore.sweep` prefers over `list_all`, and act as a durable FIFO work queue via `claim_next()` (atomic across tasks and processes), `reset_phase()` (startup crash recovery) and `count_by_phase()` (queue-depth gauges); `common.jobs.worker.WorkerPool` runs N claim loops against them (wake/poll, crash recovery, `on_finish` metrics hook) and `common.jobs.payloads.FilePayloadStore` keeps oversized job inputs on disk so queued work survives restarts — `ai/classifier/jobs/queue.py` wires the two together. `common.jobs.limits.ConcurrencyLimit` is the process-wide, event-loop-safe semaphore (with `in_flight` / `peak`) a job's inner work is bounded with — the classifier holds two, for model calls and OCR passes; `async with limit.hold(n)` takes n slots at once for one request that costs n on the far side (the classifier's sampling confidence via `n_param`), collected under a per-loop gate so two multi-slot holders never deadlock on half each (`in_flight` / `peak` count slots; n above `limit` is a `ValueError`). Plus a `build_router` FastAPI factory for the standard `GET /jobs`, `GET /jobs/{id}`, `POST /jobs/{id}/cancel`, `DELETE /jobs/{id}` endpoints (auto-detects sync vs async). `common.jobs.progress.ProgressGauge` (stdlib only) is a job's progress gauge: stages weighted to 100 (`percent = Σ completed weights + weight × index / length`), advanced by the ContextVar-resolved helpers `checkpoint()` (which also writes the `[progress 43%] units 7/12: <label>` log line) / `plan()` / `task()` — no-ops outside a gauge — under a `threading.Lock`, and flushed by `async with gauge.running()` about once a second, with a final `done` / `failed` flush before the handler returns; a store error never fails the job. `common.jobs.progress_postgres.PostgresProgressStore` keeps the snapshot in `jobs.metadata.progress` and one `job_progress` row per event (FK to `jobs(id) ON DELETE CASCADE`, so `init()` runs after the registry's), and `common.jobs.router.build_progress_router` serves `GET /jobs/{job_id}/progress` — used by `classifier`. Backend selection guidance: [`src/common/jobs/__init__.py`](src/common/jobs/__init__.py).
